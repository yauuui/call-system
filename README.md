# Call System

架電カウント・KPI管理・ステータス分析を行う単一HTMLファイル（`index.html`）+ Firestore構成のアプリです。

## 追加機能

### 1. フローティング小窓モード（最小化・他のタブに切り替えても表示され続ける）

トップバーの最小化ボタン（⤢アイコン）を押すと、タイマーとカウントパネルだけの小さな別ウィンドウが開きます。ページ内で折りたたむだけだと別のブラウザタブに切り替えた瞬間に隠れてしまうため、実際には本体とは別の「ウィンドウ」として切り出す方式にしています。

- **Chrome / Edge（116以降）**: [Document Picture-in-Picture API](https://developer.chrome.com/docs/web-platform/document-picture-in-picture) を使い、常に最前面に浮く小窓として表示されます。他のブラウザタブはもちろん、他のアプリを前面に出していても表示され続けます。
- **上記以外のブラウザ**: 通常のポップアップウィンドウとして開きます（ポップアップブロックの許可が必要な場合があります）。別ウィンドウなので他のタブに切り替えても表示され続けますが、常に最前面には固定されません。
- どちらの場合も、タイマーの開始・停止・クリアと、架電カウントの各ステータス（受付BK・不通・担当不在・目的訴求・メリット訴求・断りづらい・クロージング・カウンター・★アポ獲得）の＋／−操作がそのまま行え、本体側のデータとリアルタイムに同期します。
- タイマーの下に「架電数/h」「受付突破率」「アポ率」を常時表示します（本体の「集計結果＆分析指標」と同じ計算式）。
- 小窓の上部で「商材」「リスト」「トーク」を切り替えられます（本体の選択欄と連動します）。
- 「カウント」「メモ」「切り返し」「再架電」タブでモードを切り替えられます。メモモードでは自由記述のテキストエリアが表示され、入力内容は担当者・日付・商材ごとに自動保存（約0.8秒のデバウンス後にクラウド/ローカルへ保存）され、小窓を閉じて開き直しても保持されます。
- 小窓右上の×ボタン、またはウィンドウを閉じる操作で、元の全画面表示に戻ります。
- 「全商材まとめ」表示中はカウント操作・メモ入力ができないため、その旨のメッセージのみ表示されます。

他の作業をしながら架電記録だけを続けたい場合に使用してください。

### 2. リスト/トーク分析（アカウントごとに管理）

架電パネルの「商材」の隣に「リスト」「トーク」の選択欄があります。

- トップバーの「リスト/トーク」ボタンから、自分専用の「リスト」（製造業新規リスト・担当BKリスト・シャッフルリスト等）と「トーク」（トークスクリプトのバージョン）を追加・削除できます。**ここで追加したリスト・トークはログイン中の自分のアカウントにのみ表示され、他のメンバーには表示されません。**
- トークは名前だけでなく、台本の本文（内容）を保存できます。内容を編集すると自動的に変更履歴が残り、「履歴」ボタンから過去のバージョンとの差分（追加された行・削除された行）を確認できます。
- 架電パネルでリスト・トークを選択してカウントすると、その数値はリスト／トークごとにも記録されます。同じ日・同じ商材の中で何度でも切り替え可能です（切り替えても、既存の「本日の集計」等の数値には一切影響しません）。
- ある組み合わせ（リスト×トーク）で最初にカウントした時点のトーク内容は、そのときの記録にスナップショットとして保存されます。後でトークの内容を編集しても、過去の記録を振り返ったときに「当時使っていた内容」が分かるようにするためです。
- 「リスト/トーク分析」タブで、リスト別・トーク別・リスト×トーク別に数値（受付突破率・アポ率・架電数/h、担当BK内訳＝目的／メリット(機能)／メリット(ベネ)／断りづらい／クロージング／カウンター等）を比較できます。
- 「ステータス分析」タブのフィルターにも「リスト」「トーク」を追加しました。特定のリストやトークに絞り込むと、総架電数・受付突破率・アポ率・コール転換ファネル・ステージ別詳細分析・日別の推移が、その絞り込み条件のデータだけで再計算されます。「時間帯ごとの推移」系の3つのグラフも、リスト／トーク単位で記録している時間帯別の内訳から再計算されます。ただし、リスト／トーク単位の時間帯別の内訳はこの記録を始めた後の架電分しかないため、それ以前の記録が対象に含まれる場合は、時間帯が不明な件数がグラフの上に注記として表示されます。
- 「ステータス分析」タブに「比較モード」を追加しました。右上のスイッチをONにすると、「比較A」「比較B」の2つの条件（アカウント・商材・リスト・トーク・期間）をそれぞれ独立して指定でき、それぞれの総架電数・受付突破率・アポ率・ステータス内訳（ドーナツグラフ）・コール転換ファネル・ステージ別詳細分析を横に並べて見比べられます。各パネルの見出しは自由にリネームできます（例：「Aチーム」「Bチーム」）。
- 「コール転換ファネル」の各バーに、総架電数に対する到達率（例：「30件（総架電比 40.0%）」）を表示するようにしました。段階間の通過率（↓の数値）に加えて、全体のうち何割がその段階まで到達したかを、別グラフを見ることなくファネル1つで確認できます。

### 3. コールカウント画面

一般的なノートPC（1366×768）でも、スクロールせずに入力ボタンがすべて見える配置にしています。

- **1行目**：日付・商材・リスト・トークの選択と、報告／日報／振返り／CSV のボタン
- **状況帯**：タイマー、受付突破率・受注率・担当受注率・架電数/h、アポ進捗（クリックで目標の編集欄を開く）、ペース予測（「あと2件｜必要 10.0件/h」。緑＝今のペースで足りる／赤＝足りない）
- **モチベーション帯**
  - 次のアポまで：1アポあたりの架電数を1周とするゲージ。断られた架電でも進みます
  - 自己ベスト：1日の架電数の過去最高と比べます。目標達成の連続日数（🔥）も表示します
  - チームの温度計：チーム総アポ／目標（KPI/KGI のシフトの予想合計）。届いた👏の数も表示します
- **架電入力パネル**：通話が終わった段階を押す流れ図です。1段目は担当につながる前に終わったもの（受付BK・不通・担当不在）、2段目は担当と話した後にどこで終わったか（目的 › … › カウンター › ★アポ）を押します
  - コーチ欄：状況に合わせた一言（始業直後・午前と午後の比較・アポの間隔・終業間際・達成時）と、切り返しトークの検索欄
  - 見出しに「前回のアポから◯件目」、直前の操作の取り消しバー
- **画面の下のほう**：あなたの成長（今週と先週の比較・バッジ）、目標の編集・ペース予測の詳細・タイマーの手動設定、時間帯ごとの分析、今日の架電履歴、メンバーランキング

#### キーボードショートカット
- `1`〜`9`・`0`：パネルの並び順どおりに＋1（受付BK=`1` … カウンター=`9`、★アポ獲得=`0`）。`Shift`＋数字で−1。テンキーも使えます
- `Ctrl+Z` / `⌘+Z`：直前のカウント操作を取り消す（記録したときの時間帯・リスト/トークから正しく戻します）
- 入力欄の操作中、モーダル表示中、他のタブの表示中、全商材まとめでは反応しません。小窓でも使えます

#### ペース予測・スプリント・日報
- ペース予測：アポ目標までに必要な架電数と、終業（KPI/KGI のシフト終了、なければ18:00）までに必要なペースを見積もります。1アポあたりの架電数は当日の実績、なければ過去30日の同じ商材の実績を使います
- スプリント：状況帯の「🏁 スプリント」から、15/25/30分の集中タイムを目標コール数つきで始めます。終了時に結果と前回比を通知します
- 日報：「日報」ボタン（終業後はコーチ欄からも）で、今日のハイライトと Slack に貼れる日報の文章を作ります

### 4. チームで喜ぶ・成長を見える化する

- アポ獲得時の演出：本人の画面に短い紙吹雪と「★ アポ獲得！」を表示します。紙吹雪・効果音のON/OFFは端末ごとに設定でき、効果音の初期設定はOFFです
- 👏 拍手：他のメンバーのアポ通知から拍手を送れます。届いた拍手は通知され、チームの温度計に表示されます
- 連続記録・週次の振り返り・バッジ：比べる相手は先週の自分です。良くなった指標から先に表示し、バッジは質・粘り・継続に連動させています（架電数そのものには報酬を付けません）

### 5. 切り返しトーク・再架電リマインダー

- 切り返しトークの検索：ナレッジベースの「カウンター」（チーム共有＋個人用）を、断り文句・本文・解説から検索できます。「断りづらい」「カウンター」を押すと、よく使う切り返しをコーチ欄に表示します（「使った👍」の回数でよく使う順に並べます）
- 再架電リマインダー：トップバーの「再架電」から会社名・日時・メモを登録すると、時間になったら本体・小窓・ブラウザの通知で知らせます。本人のアカウントにだけ表示されます

### 6. 分析の追加機能

- ステータス分析：**弱点診断**（各段階の通過率をチームの中央値と比べ、弱点にはナレッジベースへのリンクを表示。AIは使いません）
- リスト/トーク分析：列見出しで並べ替え、指標を選べる比較グラフ、件数の少ないグループの「参考値」表示、**曜日×時間帯ヒートマップ**、**トークのA/B判定**（差が誤差かどうかと、判定までに必要な件数）

### 7. 大画面モード・スマホ・ダークモード

- 大画面モード：トップバーのグラフのボタンで、オフィス掲示用の画面（チーム総アポ・メンバーの進捗・アポ速報）に切り替えます。Esc で戻ります
- スマホ：幅768px以下では画面下のタブバーになり、コールカウント画面は入力パネルが1画面に収まる「リモコン」型の表示になります
- PWA（ホーム画面に追加）：`index.html` と同じ場所に `manifest.json`・`sw.js`・`icons/` を置き、**https で配信**すると、ホーム画面に追加してアプリのように起動できます。通信できないときも、保存済みの画面を表示します（データの同期には接続が必要です）
- ダークモード：トップバーの 🌙 で切り替えます（端末ごとの設定）

### 使い方マニュアル

左のメニューの「使い方」に、アプリの使い方マニュアルを載せています。目次から各章へ移動でき、上の検索欄でマニュアル内を検索できます（該当する章だけを表示します）。本文は `index.html` の `page-manual` に直接書いた静的なHTMLです。**機能や画面の文言を変えたときは、このマニュアルも合わせて直してください。**

### データの補足（Firestore / 端末）

- `kaden_records` の各レコードに、`callLog`（1件ずつの架電ログ）と `sessionsByKey[].hourly`（リスト×トーク別の時間帯別内訳）を追加しています。既存のフィールドの意味は変わりません
- 新しいコレクション：`kaden_claps`（拍手。`{受け取る人}_{日付}`）、`kaden_callbacks`（再架電リマインダー。`{ユーザー}`）。セキュリティルールでコレクションごとに許可を設定している場合は、この2つの読み書きの許可を追加してください
- 端末ごとの設定（localStorage）：テーマ、アポ獲得時の演出、切り返しの「使った」回数、スプリントの状態と履歴

### 8. AI分析（苦手傾向と改善方法）

「ステータス分析」タブの一番下に「AI分析（苦手傾向と改善方法）」カードを追加しました。フィルター（アカウント・商材・期間）を選んで「AIで分析する」を押すと、選択した担当者の架電プロセス（受付突破 → 担当接続 → 目的訴求 → メリット訴求 → 断り対応 → クロージング → アポ獲得）のどこに弱点があるかをAIが分析し、改善方法を提案します。

この機能を使うには、AI APIキーを安全に扱うための Cloud Function を1つデプロイする必要があります（下記手順）。**AI APIキーをフロントエンド（index.html）に直接書き込むことは絶対にしないでください**。誰でもブラウザの開発者ツールから閲覧・抽出できてしまいます。

#### デプロイ手順

1. Firebase CLI をインストールし、このプロジェクト（`callsystem-a29c4`）にログインします。
   ```
   npm install -g firebase-tools
   firebase login
   ```
2. `functions/` ディレクトリの依存パッケージをインストールします。
   ```
   cd functions
   npm install
   cd ..
   ```
3. Anthropic の API キーを Cloud Functions のシークレットとして登録します（値はコマンド実行時にプロンプトで入力するため、リポジトリやシェル履歴には残りません）。
   ```
   firebase functions:secrets:set ANTHROPIC_API_KEY
   ```
4. デプロイします。
   ```
   firebase deploy --only functions
   ```
5. デプロイ完了時に表示される関数のURL（例: `https://asia-northeast1-callsystem-a29c4.cloudfunctions.net/analyzeWeakness`）を、`index.html` 内の `AI_ANALYZE_FUNCTION_URL` 定数に設定します。

```js
const AI_ANALYZE_FUNCTION_URL = "https://asia-northeast1-callsystem-a29c4.cloudfunctions.net/analyzeWeakness";
```

設定後、`index.html` を再度公開（デプロイ）してください。

#### 補足

- 既定では Anthropic の Claude API（モデル: `claude-sonnet-5`）を利用します。別のAI APIを使いたい場合は `functions/index.js` の `fetch` 呼び出し部分を変更してください。
- `functions/index.js` はサーバー側（Cloud Functions実行環境）でのみAPIキーを読み込むため、ブラウザにキーが渡ることはありません。
- 呼び出し回数やコストを制限したい場合は、Firebase App Check の導入や、Firestoreへの呼び出しログ記録・レート制限の追加を検討してください（本実装には含まれていません）。
